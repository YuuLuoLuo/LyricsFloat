## 歌词板（Lyric Board）方案设计

产出：`歌词板-方案设计-v1.md`（完整方案，未写代码）。

### 确定的关键决策
- 技术栈：**Tauri 2 + Rust + Vue 3 + WebView2**（用户已确认）
- 目标系统：**仅优化 Windows 11 22H2+**（用户已确认），Win10 只保证能跑、玻璃降级纯色
- 窗口：单窗口，透明 + 运行时用 `window-vibrancy` 的 `apply_acrylic` / `clear_acrylic` 叠加移除磨砂

### 推导出的核心结论（后续开发必须遵守）
1. **Electron 不可选**：`backgroundMaterial` 与 `transparent: true` 互斥（分层窗口会让 DWM 材质失效），无法单窗口实现"透明 ⇄ 磨砂"动态切换，只能拆双窗口。这是选 Tauri 的决定性理由。
2. 交互模型收敛为两个布尔量：`locked` / `hovered` 三态（锁定、解锁静止、解锁悬停）。锁定与"解锁静止"视觉完全一致。
3. **悬停检测不能依赖 mouseenter**，用 Rust 侧 ~60Hz 轮询全局光标坐标；进入扩 6px、离开收 40px、延迟 300ms 收玻璃。
4. 播放状态走 **Windows SMTC**（与播放器无关，覆盖网易云/QQ音乐/浏览器），而非钩网易云插件；link-rs 只负责歌词查询。
5. 时间同步：锚点外推 + 漂移修正（>300ms 直接跳，<300ms 按 40ms 步长收敛）。
6. 歌词匹配必须校验时长差（>5s 判负），防止同名现场版/翻唱错配。

### 风险闸门
P0 技术验证（透明窗口 + 动态磨砂开关 + 穿透 + 悬停）是唯一闸门。若 `window-vibrancy` 在 Win11 24H2 表现不达标，切 Plan B 双窗口（玻璃层 SystemBackdropType=Acrylic + 文字层透明窗口），逻辑收在 `EffectController` 后面。

### 待确认（不阻塞）
- 网易云是否需登录态（影响 YRC 逐字歌词命中率）
- 是否接 QQ 音乐源
- 默认展示形式：7 行滚动 vs 单行聚焦

## v0.2 反馈修复（同日 14:35）

用户实测后提了 8 条问题，全部处理。**产物 `release/lyric-board.exe` 4.7MB。**

### 白底 / 直角外框的根因（重要，别忘）
三个原因叠在一起，缺一不可修：
1. **`backdrop-filter` 在透明窗口里会强制图层合成** → 整块被合成为白底。已全局移除，模糊改由系统亚克力负责。
2. **WebView2 默认背景是白色**，`transparent: true` 不足以保证透明 → 必须显式 `win.set_background_color(Some(Color(0,0,0,0)))`。
3. **DWM 背板是矩形**，CSS 圆角管不住 → 用 `SetWindowRgn(CreateRoundRectRgn)` 把窗口形状裁成圆角，随尺寸/圆角变化重设。

### 其它关键修复
- **磨砂偏白**：`window-vibrancy` 已弃用。它在 Win11 22H2+ 走 DWM 接管，跟随系统主题取色，浅色主题下就是一片白灰。改为自己调 `SetWindowCompositionAttribute`，同时打 `DWMWA_USE_IMMERSIVE_DARK_MODE`。
- **歌词不显示**：接入 SMTC（`windows` crate 的 `Media_Control`）+ 网易云搜索/歌词 + lrclib 兜底 + `%APPDATA%\lyric-board\lyrics` 缓存。`cargo test` 联网验证通过（晴天/周杰伦命中，制作人名单过滤，lrclib 可用）。
  - 关键细节：网易云最高分候选常是"暂无歌词"的翻唱，必须按分数试前 3 个，并用 `sanitize()` 过滤占位文本 + 作词/作曲等 staff 行。
- **无法拖动**：`getCurrentWindow().startDragging()`（pointerdown，排除按钮），位置存 localStorage，启动时 `restorePosition()` 再 show。
  - 因为系统拖动会吃掉双击事件，改用「右键菜单 + 托盘」进设置，不做双击。
- **调尺寸抽搐**：根因是「CSS px 宽度 + 原生 resize」两套尺寸打架，且鼠标不在词板上时玻璃会隐藏（看不到预览）。改为 CSS 只吃 100vw/100vh，尺寸唯一由原生窗口决定；设置页打开时 Rust `FORCE_REVEAL` 强制显形。
- **托盘图标**：`make-icon.mjs` 增加 PNG 输出（自带 zlib + CRC32），托盘 `include_bytes!("../icons/32x32.png")`。
- **设置独立成窗口**：新增 `settings` 窗口（860×680，无边框透明 + 自绘标题栏），`main.ts` 按 window label 分流到 `App.vue` / `SettingsApp.vue`。
- **新增设置**：开机自启（`reg.exe` 写 HKCU Run，零依赖）、总在最前、锁定、退出；外观新增字体/字重/三色/描边宽度与颜色/阴影。
- 跨窗口同步：localStorage + `storage` 事件 + 900ms 轮询双保险（`pullSettings` 比对序列化文本）。

## 第五轮反馈修复（16:30）
- **进度不同步（主因）**：Rust 侧 SMTC 的 `position` 单位是**秒**，前端 `PlayClock` 全程用**毫秒**，直接把秒喂进去 → 时钟永远停在几百毫秒处。表现就是"设置里进度正常但歌词卡在第一句"，且首句在 0 附近反复触发当前/非当前切换 → 看着像闪烁。`applyTick` 改为 `posMs = position * 1000`。
- 播放判定重写：原来的 "连续 3 个 tick 进度在涨" 在 timeline 每 5 秒才刷新时永远攒不够，时钟一直冻着。改成记录 `lastAdvanceAt`，"最近 2.5 秒进度有前进" 即视为播放。
- 旧值防回拽：Rust 增加 `fresh`（LastUpdatedTime 距今 ≤2.5s）；前端遇到 `fresh=false` 且倒退 <300ms 的采样直接忽略，避免歌词被旧值拽回上一句；>8s 的倒退（拖进度条）仍采纳。
- 外推上限 2s → 15s：播放器普遍 1~5 秒才刷新一次 timeline，只认 2 秒会恒定落后半句；超过 15 秒视为"不维护该字段"，不外推（防荒谬值把歌词推到片尾）。
- 换歌时 `lastRaw = NaN`，避免新歌起始进度与旧值相同被判成"没变化"。
- **窗口阴影**：DWM 只给带框架样式的窗口投影。诊断出 tao 给词板留了 `WS_CAPTION`（style 0x14C80000）。`effects::strip_shadow` 摘掉 CAPTION/THICKFRAME/SYSMENU + `DwmExtendFrameIntoClientArea(0)` 重算非客户区，再补回圆角与无边框色。**只在 setup 里摘一次无效**（显示后样式又回来了），改为 hover 线程每 60 tick（≈1s）复查 `has_frame_style` 并按需重摘。实测 style 变成 0x14000000。
- 字体下拉：`select` 加 `color-scheme: dark` + `option` 显式底色/字色，修原生列表白底浅字。
- 黑字模板：描边 0.9 → 2.4px（`-webkit-text-stroke` 是居中描边，视觉厚度只有一半），`.txt` 加 `paint-order: stroke fill`；预览纸张跟随模板（黑字垫浅色壁纸、白字垫深色）。
- 设置页新增「时钟」行（歌词时钟读数），与「进度」对照即可一眼判断同步链路是否正常。
- **验证手法（重要）**：桌面截图/PrintWindow 必须先 `SetProcessDpiAwarenessContext(-4)`，否则拿到的是被虚拟化过的坐标，只能抓到窗口左上角一块，会被误读成"歌词不居中/被切"。实测词板真实尺寸 960x585（CSS 640x390 × dpr1.5），当前句中心 y=292/585 —— 居中本来就是对的。

- **已在播放时打开词板 → 上下两句抽搐**：三处叠加。
  1) `applyTick` 里顺序反了：先 `clock.sync` 再 `setPlaying`。播放器报 Paused 时时钟按暂停处理，sync 走"偏差>120 就 seek"，于是每 250ms 硬跳一次。改为先判 `moving`（最近 2.5s 进度有前进）再 `setPlaying`，最后才 sync。
  2) `PlayClock.sync` 以前把"读数比外推小"的差当误差按 `drift` 吸收，等于每拍把时钟往回拽一次，形成 ±几百毫秒的锯齿，正好卡在句子边界上来回跳。改为**只向前校正**：diff<0 直接忽略（除非倒退 >8s 视为拖进度条才 seek）；diff<120ms 视为噪声不校正；drift 上限 400ms。
  3) `LyricStage` 当前行加 150ms 迟滞：只有时间明确越过下一句起点才换行，往回同理。
- **偶尔出现"歌词板"标题文字**：tao 给无边框窗口留了 WS_CAPTION 样式位，DWM 会照窗口标题在左上角画字。而且"上一版摘 CAPTION → 被 tao 加回 → 1 秒后再摘"正是它概率闪现的原因。现在不动样式位，直接把窗口标题设为空串。
- **悬停时外框阴影**：根因是 DWM 的窗口级圆角（DWMWA_WINDOW_CORNER_PREFERENCE=ROUND）必然附带一层投影。改为 **SetWindowRgn 圆角区域**裁形状 + DWMWA_WINDOW_CORNER_PREFERENCE=DONOTROUND。带区域的窗口 DWM 不投影、也不画框架。
  - 半径 8 逻辑像素，用 GetDpiForWindow 换算（该进程里返回 96，区域坐标是逻辑像素，正好 1:1 对应 CSS）。
  - 尺寸变化后必须重裁；`set_size` 异步生效，所以改尺寸时立刻裁一次、90ms 后再按真实尺寸补一次。
- **验证手法（重要）**：造一块纯白 WS_POPUP 窗口垫在词板后面，再抓屏量窗口外 3~130px 的亮度。实测全 255（无阴影）；逐像素描圆角弧线，dx=0→dy=11、dx=4→3、dx=12→0，即半径 12 物理像素 = 8 CSS px，圆角保留。深色壁纸上量不出阴影，必须垫白底。

## 第八轮：左右对齐溢出修复 + 指针排布 + 设置收回程序内（18:26）

## 第九轮：指针排布收口 + 设置页合并（18:54）
- **指针排布右锚点方向错了**：只把 `transform-origin` 改到右边是不够的，
  旋转方向也要镜像（右锚点绕右边缘转时，正角度会让下方句往**上**甩，
  看起来像绕左边转）。`rotate = d * 3deg * (align === 'right' ? -1 : 1)`。
- **缩放原点改成 px**：`left/right center` 会让内边距跟着放大，
  当前行 1.4 倍时右端反而内缩 10px、和上下句对不齐。
  改成 `26px center` / `stageW-26px center`，正好压在文字边上，实测各行右沿 494~496。
- **指针排布取消居中**：`H_ALIGNS` 在 pivot 下只给 左/右；切模式时 center 自动落 left；
  `store.tame()` 也把存量的 pivot+center 收到 left。
  模糊从 `min(11, 2.4+ad*1.9)` 降到 `min(6, 1.2+ad*1)`，透明度 0.52-0.1*ad。
- **面板并入外观**，只剩 常规 / 外观 两个标签页。外观顺序：
  展示形式 → 卡片布局 → 词板尺寸 → 字体 → 对齐 → 颜色 → 描边与阴影 → 动效 → 玻璃背景。
  常规顺序：当前播放 → 同步 → 行为（自启/总在最前/锁定）→ 设置文件。
- **后开词板偶发不同步（根因）**：启动时读到的 position 若是"未外推"的旧值，
  时钟被 seek 到旧位置后**永远回不来** —— 之后两边都按 1× 走，差值恒定，
  `clock.sync` 又只做正向校正。三点修法：
  1. 客户端按「这个 position 数值首次出现的时刻」补足流逝时间（Rust 没外推时兜底）；
  2. `calibrate()`：正向照旧（>400 硬跳、120-400 走 drift），
     反向要**连续 3 次且 >500ms** 才回锚（单次滞后仍忽略，不会重现抽搐）；
  3. 首次读到的数值不算"在走"（暂停时时钟别先跑起来，否则歌词白白超前 0.5s）。
- 设置页「进度」改用一位小数（`fmtTenth`），和「时钟」同精度，两行能直接对着看。
- 文案瘦身：设置文件的小字改成「配置随软件本体保存。把导出的设置文件拖入窗口即可导入。」
- **教训**：验证完必须用 `quit_app` 优雅退出，`taskkill` 会把还没落盘的 localStorage
  打回去，下次启动反而把测试状态带回来。

## 第十轮：前奏/尾奏让空当前格（19:05）
- `cur` 从「夹到 0」改成三种状态：`-1` 前奏 / `0..n-1` 正常 / `n` 尾奏。
  两端都不点亮任何一行——首句、尾句只作为普通句子出现。
- 关键手法：`railY` 用**未夹紧**的 cur（-1 或 n），轨道整体多滚一行，
  正中那一格自然空出；`rowLook` 的距离也按真实 cur 算，
  于是首句在前奏时天然变成"下一句"（d=1）自动变暗。
- `locate()` + `stepLine()` 都认两端空档，并各带 150ms 迟滞
  （末尾 HYST 内保持空白，避免在 last.end 附近反复闪）。
- focus/duet 在没有当前句时，把最近的一句按 0.45 / 0.6 透明度放出来 ——
  全程空白太像程序没跑。
- 设置页预览：词板会让空，但预览条只有 112px，让空会把那一句顶出去，
  所以预览把时间夹在 `[line.start, line.end-1]` 里，永远按"正在唱"渲染。
- 验证：把 `lyric.lyric.offsetMs` 改成 +60000 / -180000 再 reload 词板页，
  可稳定复现前奏/尾奏；实测两端 `is-current` 均为 0 行，
  前奏首句落在中心下一行、尾奏末句滚到中心上方。
